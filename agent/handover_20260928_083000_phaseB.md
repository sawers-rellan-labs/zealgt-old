## Entries (`--workflow cram`, `--entry ...`), store layout, params
- `read_demultiplexing --libraries <lib>` runs DEMUX → DEMUX_QC → TRIMMOMATIC → FASTQC → ALIGN_MARKDUP → SAMTOOLS_STATS + PICARD → PROVENANCE, then REGISTRY and MultiQC per library.
- `read_trimming --input <sheet>` starts from demuxed FASTQs (assets/schema_input.json: sample,fastq_1,fastq_2,crop_r1,crop_r2). Every sample must be in meta/samples.csv. The **crop columns are required**. Cropping is not implemented, so anything but 0/0 is refused. Nirwan's filtered_S batch-1 reads really need 12/0 (the R1 randomer), which means they cannot go through the entry until a crop step exists.
- `read_alignment --input <sheet>` starts from trimmed FASTQs and runs ALIGN_MARKDUP onward.
- `markdup_import [--input meta/dev_import.csv] [--import_samples a,b] [--import_sets x]` runs MARKDUP_IMPORT → QC → PROVENANCE. It keeps the input header RG only if that RG's SM equals the sample id. Otherwise it uses the sheet RG and drops the old @RG lines. The dev_import `read_groups` column is ignored.
- Store root is `--store` (default ZEAL/store). It becomes `<store>/subsample_<N>` with `--subsample N`, and `<outdir>/store_stub` under the stub profile. Stub runs refuse any store that is not named store_stub* or that sits inside ZEAL/store.
  - `demux_qc/<lib>.{tsv,summary.tsv,read_start.tsv,cutadapt.json,cutadapt.log}` (storeDir)
  - `cram/<s>.{cram,cram.crai,markdup.stats,align_markdup.versions.yml,provenance.json}` (storeDir), plus `<s>.stats` and `<s>.CollectWgsMetrics.coverage_metrics`. Those two are *published* there, because storeDir rejects nf-core's `eval` version outputs. The workflow skips QC whose file is already stored.
  - `cram_import/` (the same layout for imports), and `registry/<lib>.registry.tsv`.
- Registry rules:
  - `assets/registry_seed.csv` counts as registered. It lists PLAN §0's demuxed libraries: 1A 1B 2A 2B 2F 2H 3B–3E 4E–4G, and V22A–H, V23A–H, V24A–B.
  - Any `<store>/registry/*.registry.tsv` also counts.
  - A registered library is refused unless `--force_demux <lib>`. Use the underscore form; the plan's `--force-demux` spelling is not the param name.
  - `--max_libraries` defaults to 1, and DEMUX has maxForks 1.
- Samples with a stored CRAM are not trimmed or aligned again.
- `--run_id` is required on hazel.
- Settings are params and are recorded in provenance. All are hidden from normal use; change them only deliberately.
  - `read_structure_symmetric` = '6B2S+T 6B2S+T' (BC1, batch 2).
  - `read_structure_r1_only` = '8B12S+T 8S+T' (batch 1, raw tars job 969161).
  - `demux_args` = '-e 0 --no-indels --discard-untrimmed -Z'.
  - `trim_adapters` = assets/adapters/TruSeq3-PE-2.fa (as shipped with trimmomatic 0.39), `trim_illuminaclip` = 2:30:10, `trim_args` = 'LEADING:3 TRAILING:3 SLIDINGWINDOW:4:15 MINLEN:36' (no -phred33, see open item 14a; phred auto-detected).
  - `align_args` = '-x sr', `markdup_args` = '-d 2500'.
- **Deviation from zealbc1:** the anchored pattern `^<barcode>NN` removes the 2 skip bases (6B2S+T) from both reads. zealbc1's `^<barcode>` left them in every read.

6. Batch-1 demux from the tars (`tar -xOf` per member, R1-only pattern + `-U 8`) is wired but untested on real data. Each member extraction scans the tar sequentially.
7. minibwa writes no MD tag unless `-b MD` (coordinator, Phase C2). Nothing downstream in the CRAM workflow reads MD. If the genotype workflow needs it, add `-b MD` to `align_args` (this changes provenance and the ALIGN hash only; stored CRAMs are unaffected).
