## What changed
1. **scripts/build_envs.sh: prefixes keyed on content only.**
   - Prefix = `/share/maize/frodrig4/conda/zealgt/<first dependency>-<sha8>`. sha8 = sha256 of the environment.yml with comment
     lines, blank lines, trailing comments and `name:` removed, plus the build.sh bytes. `<first dependency>` is the package name
     of the yml's first dependency, so the name is a function of content alone: identical envs share one prefix in every branch
     built into the same root, and a comment edit changes nothing.
   - Chosen over `<first-module>-<sha8>`: the module name would differ per branch for identical content (e.g. genotype's
     `pooled_likelihood_tiers` vs simplify's `demux_qc`), and a new module sorting first would rename a prefix.
   - `--list`: one row per process (id, process, env dir, sha8, prefix); the `nextflow` row first, same 5 columns, so
     `submit_head_job.sbatch` / `test_cache.sbatch` work unchanged.
   - `--prefixes`: prefix -> env ids / processes / state on disk.
   - `--write-config`: one `withName` per process; DEMUX_QC, PROVENANCE, REGISTRY -> `python-ab5d3d87`.
   - `--check-config` is now a step of `scripts/run_checks.sh` (also `--quick`).
   - `--list-stale [--all-refs | <ref>...]`: directories under the root that neither this checkout nor the named git refs reference.
     For each ref it reads the committed `conf/env_prefixes.config` (compared by name under ZG_ENV_ROOT), plus that ref's launcher
     prefix under both the old and the new naming. It only lists, never removes.
   - `--inodes [<prefix>...]`: own inodes (`find <prefix> ! -type f -o -type f -links 1 | wc -l`) and all entries; the default is
     every dir under the root.
   - Builds go per prefix, running the smoke tests of every env id sharing it. Manifest rows are per prefix, with a new
     `own_inodes` column. The script never deletes anything.
   - `build_envs.sbatch` accepts `ZG_REPO`.
   - Laptop test on a fake root that mirrors hazel's dir names: `agent/20260929_120000_test_build_envs_stale.{sh,txt}`. With
     `origin/genotype origin/main` or `--all-refs`, only `nextflow-199bd219` is stale.
2. **MERGE_LANES** has its own `environment.yml`: `conda-forge::coreutils=9.11=h280c20c_0`, smoke `cat --version`.
   `envs/process_aliases.tsv` was removed with `git rm`; alias support stays in the script, for `include { X as Y }`.

   - Net: no version-output change, and no consumer change (PROVENANCE stage-1 tools, MultiQC collation).

     was not done here.
